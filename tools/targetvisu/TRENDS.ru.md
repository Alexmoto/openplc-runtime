# Тренды в TargetVisu — первая версия

Тренд — отдельный графический элемент в OpenPLC Editor / TargetVisu. Его источник —
числовая переменная PLC (SINT..LREAL, кроме BOOL); значения могут поступать в
программу из Modbus, MQTT или внутренних вычислений.

## Что доступно

- До 4 кривых одного графика: переменная, подпись, цвет.
- До 8 графиков на весь документ TargetVisu.
- Интервал записи: 0,5 / 1 / 2 / 5 / 10 / 30 / 60 секунд в интерфейсе Editor.
- Окно времени: 1, 5, 15, 30, 60 минут.
- Не больше 600 отсчётов в настроенном окне. Для навигации по прошлым
  значениям сервис дополнительно удерживает до 901 отсчёта на график,
  но не более четырёх настроенных интервалов. При увеличении окна Editor
  автоматически увеличивает интервал, если необходимо.
- Фиксированная шкала Y (Minimum и Maximum у элемента) или Auto scale.
- Время на оси X отображается по локальному времени компьютера Runtime.
- При отсутствии связи линия прерывается, старые отсчёты постепенно уходят из окна.
- Отображение обновляется примерно раз в секунду, опрос переменных — в общем цикле
  сервиса TargetVisu с периодом refreshMs.

## Как настроить

1. В OpenPLC Editor откройте TargetVisu, выберите экран и нажмите **+ Trend**.
2. В правой панели укажите **History window**, **Sample period**, при необходимости
   включите **Auto scale Y**. В фиксированном режиме настройте **Minimum** и **Maximum**.
3. Нажмите **+ Add curve**; выберите переменную, подпись и цвет. Добавьте остальные
   кривые при необходимости.
4. Скомпилируйте и загрузите проект вместе с его TargetVisu-данными.
5. Перезапустите сервис TargetVisu с новой версией исходников, затем окно TargetVisu.

## Масштабирование и прокрутка на экране Runtime

Внизу Trend размещены кнопки. На узких элементах они переносятся в две строки:

| Кнопка | Функция |
| --- | --- |
| **X+** / **X-** | Увеличить/уменьшить масштаб времени (от 10 секунд до 4× настроенного окна) |
| **<** / **>** | Прокрутка к более раннему/позднему времени на четверть окна |
| **Y+** / **Y-** | Приблизить/отдалить значения по вертикали |
| **^** / **v** | Сдвинуть диапазон Y вверх/вниз |
| **LIVE** | Вернуть текущее время, начальное окно X и исходное авто-/фиксированное масштабирование Y |

При прокрутке к прошлому временной интервал фиксируется и не движется
вместе с текущим временем. При **LIVE** график снова следует за текущим
временем. Первая операция Y+ / Y- / ^ / v переключает шкалу Y в локальный
ручной режим без изменения настройки Auto scale в Editor. Окна и масштабы
каждого графика независимы; они хранятся только в памяти процесса viewer.

Эти кнопки не являются действиями PLC, не отправляют команды записи
и не меняют исходные значения. Необходим достаточный размер элемента
(рекомендуется 320×180); на слишком маленьком элементе кнопки скрыты.
Если история ещё не накоплена, прокручивать в прошлое будет нечего.

SVG в Editor показывает **условные линии** с надписью `Preview`, а не историю PLC.
Реальные значения отображаются только при работе сервиса Runtime.

## Архитектура

Функция реализована в Python-сервисе `tools/targetvisu`. Чтение PLC использует
существующий канал отладки с проверкой MD5, а запись в историю ведётся вне
цикла PLC. Никакого дополнительного C/C++-патча ядра для самих трендов нет.

Сервис `service.Engine` сохраняет историю в ограниченных кольцевых буферах в RAM.
Клиент окна запрашивает только графики активного экрана через
`{"op":"trends","screen":"<id>"}`. Broker не принимает произвольные PLC-адреса.

**Ограничение версии:** история сбрасывается при перезапуске Python-сервиса
TargetVisu. Архив на диске, CSV-экспорт, прокрутка старой истории и масштабирование
по времени будут отдельным этапом. Для постоянной регистрации критичных
технологических данных используйте промышленный архиватор.

## Совместимость с MQTT

Ветка `feature/targetvisu-trends` содержит изменения из
`feature/mqtt-data-source`. Тренд может читать PLC-переменную, обновляемую
MQTT-подпиской; дополнительных настроек MQTT в самом графике нет.
